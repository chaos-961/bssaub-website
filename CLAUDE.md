# BSS AUB Website

Rebuild of bssaub.com for the AUB Business Student Society. One goal drives every decision: get an AUB student to grab the membership card. Everything else (sponsors, story, animations) exists to make that decision feel obvious.

Repo: `https://github.com/chaos-961/bssaub-website.git` · Live: `https://chaos-961.github.io/bssaub-website/` (GitHub Pages via Actions; custom domain later).
Current version: **0.4.2**.

## Rules (standing, no exceptions)

1. **Git gate.** Never commit or push unless the user explicitly says commit or push in that session. "Looks good" is not authorization. Every push to `main` auto-deploys — treat push authorization as deploy authorization and say so.
2. **Version contract.** Bump `version.json` by +0.0.1 as part of each authorized push (base-10 carry: 0.0.9 → 0.1.0). Keep the three static badge fallbacks (index/404/account footers) in sync with it (two between v0.4.1 and v0.4.2, while the account page was gone; `admin.html` carries no footer and no badge, deliberately). Commit message format: `v0.1.3: short description`.
3. **No invented data.** Discounts, Instagram links, and redemption steps are never guessed. Unknown means blocked and listed, never filled with plausible garbage. Nothing marked "?" ever ships.
4. **No hyphens or dashes in user-visible copy.** Em dashes become commas, colons, or periods; titles join with "·"; compounds get rephrased ("hub led by students", not "student-led hub"). Applies to text nodes, aria-labels, alt text, titles, and meta.
5. **File content edits via the Edit/Write tools only.** PowerShell 5.1 text operations mojibake UTF-8.
6. **Feel checks on real hardware are the user's.** Headless verification covers logic, geometry, and colors; 60fps judgment is theirs.
7. **Session protocol.** Read this file, state version + open items in a line or two, await instruction. A user request is its own authorization — the rules stop AI initiative, not user freedom. Keep the version line and Open items section here current as work ships.

## Stack and shape

Vanilla JS + Vite 6 (`index.html` + `account.html` + `admin.html` + `404.html`; multi-page since the start) · GSAP + ScrollTrigger · Lenis smooth scroll · Matter.js physics · **Firebase Auth (v0.4.2, account page only, loaded with a dynamic import)** · Fraunces + Instrument Sans (self-hosted variable woff2). No other runtime deps, zero third-party scripts.

- `src/main.js` — init order matters: scroll → oceanMesh → nav → heroCard → cardName → modal → perkField → journey → sponsorCta → agencyCredit → **reveal** → footerVersion → `scroll.refresh()` → preloader last (it collects `[data-preload]` images the field creates). The preloader `onComplete` fires `heroCard.enter()`. `reveal` goes after the field and the journey because its triggers measure elements those two have just laid out; `oceanMesh` now takes `scroll` purely to read its velocity (v0.3.6 surge) and still owns no part of the page's scroll behavior. (The generative starfield background lived in this order until v0.2.5; it was extracted to the `Background Constellation` template and removed.)
- `src/data/sponsors.js` — single source of truth for every sponsor. `src/data/names.js` — the 100 first names the hero card types onto itself (v0.3.9).
- `src/modules/*` — one module per concern; `src/styles/*` — tokens.css first, then per-section files. The v0.4.2 additions: `session.js` (the display-name cookie, no Firebase, shared by index and account), `loginToast.js` + `toast.css` (the greeting), `accountAuth.js` + `auth.css` (the member page, and `auth.css` is shared with the admin gate so its primitives are named card/field/tab rather than for either page), `src/data/firebase.js` (project config, public by design), and `src/admin/*` (the plaintext dashboard that is never served).
- `public/assets/` — brand/, card/, sponsors/<category>/<id>.webp, journey/.
- `src/assets/bg/mesh.svg` — the generated background mesh. It lives in `src/`, not `public/`, so Vite resolves, hashes, and base-rewrites the `url()` in site-bg.css; a `public/` file would have to hardcode `/bssaub-website/` and break on the custom-domain flip. Regenerate with `node scripts/generate-bg-mesh.mjs [#hex]` (seeded, so output is byte identical unless the base changes). Never hand edit the SVG.
- `src/lib/mesh.js` — **the single source of truth for the mesh**: geometry, the palette ramp, the drift cycle, the swell field, and the contrast maths. Imported by `scripts/generate-bg-mesh.mjs` (writes the shipped SVG), `scripts/check-swell.mjs` (the motion gate), and `src/modules/oceanMesh.js` (builds the WebGL buffers). Never reimplement or approximate it in a second place: the static SVG is the animation's **rest state**, and if the two drifted the background would visibly jump as the canvas fades in. `DEFAULT_BASE` must stay equal to `PALETTE_CYCLE[0]` for the same reason; the build script hard fails if they differ. **Recoloring the background is one edit**: those values, then rerun the script.
  - The swell is data, not code (v0.3.4): `SWELL` is a table of sum-of-sines terms, and `swellGlsl()` **generates the shader's `swell()` function from it** while `swellAt()` evaluates the same table in JS. That is why the amplitude proof is trustworthy: the harness and the shipped shader are the same numbers by construction, not by careful copying. Verified on a real GPU at v0.3.4, agreeing to within 8 bit encoding precision (max error 0.007). Never hand edit `swell()` inside oceanMesh.js.
  - Two gates guard this file, and **both must be re-run after touching `AMP`, `SWELL`, `MESH`, or `PALETTE_CYCLE`**:
    - **Colour**, in `generate-bg-mesh.mjs`, which **refuses to write** on failure (exits 1, leaves the asset untouched), so an illegible colour cannot reach the repo by accident. It checks the still *and* the worst instant of the animated cycle with the shader dither applied. `--ink-soft` body copy on the darkest facet is the binding number, floor 4.5:1. A dev-only `COLORS` picker panel existed briefly at v0.3.2 and was removed the same day on the user's word; do not rebuild it without a fresh brief.
    - **Motion**, in `scripts/check-swell.mjs` (v0.3.4), which walks the real lattice through a 240s sweep at both the desktop amplitude and the capped mobile one and fails on any inverted facet, on any facet squashed below half its rest area, or on an overscan margin too small for the worst case displacement. This is not ceremony: it **rejected the first v0.3.4 attempt** (a facet collapsed to 0.36 of rest, which reads as a crease), and the fix it forced (longer wavelengths, not lower amplitude) is what let the motion get 3x stronger at all.
- Deploy: `.github/workflows/static.yml` (push to main → build → Pages). `vite.config.js` has `base: '/bssaub-website/'`. Custom-domain flip: CNAME in public/, base to `/`, revisit 404.html's absolute icon paths.
- Clean URLs (v0.1.3, retired at v0.4.1, **back at v0.4.2**): internal links are extensionless (`account`, never `account.html`), with a `cleanUrls` middleware in `vite.config.js` giving dev and preview the behavior Pages has natively. Index and 404 need no rewrite. `CLEAN_PAGES` now holds `account` and `admin`; **a new page that wants an extensionless link adds itself there**, or it 404s in dev while working fine on Pages, and its canonical and og:url use the extensionless form. The font preload plugin came back in the same pass and now serves both gated pages.
- **CSP (v0.4.2), on account and admin only, injected at BUILD time by a `vite.config.js` plugin.** It is written there rather than into the HTML because Vite's dev server serves an inline module script (its HMR client), so a `script-src 'self'` meta tag in the source file would break `npm run dev` while looking perfect in production; `ctx.bundle` is present in build and absent in dev, which is the switch. Neither page carries **any** inline `<script>` for this reason (their `js` and `reduced-motion` root classes are set at the top of the entry module instead; index keeps its inline version because there the class gates the preloader curtain, which must be up before the bundle arrives). `style-src` keeps `'unsafe-inline'` on purpose, since GSAP writes element styles and CSS injection is not the surface worth a rewrite once script execution is locked. `frame-ancestors` is **ignored in a meta CSP by spec** and GitHub Pages cannot set headers, so clickjacking is covered by the frame bust at the bottom of `src/admin.js`. Verified in `vite preview`: zero console errors on either page, and the injected tag lands at byte 642 (account) and 466 (admin), which keeps the charset meta inside the first 1024 bytes the parser needs it in.
- Local run: `run-local.bat` (untracked, gitignored — user helper): opens the already-running server if 5173 is busy, else installs deps if needed and starts `vite --open`.

- **Background (v0.3.1, user brief): a low poly triangle mesh**, `div.site-bg` first in `<body>` on every page, styled by `src/styles/site-bg.css`, imported by all four entries (main.js, page.js, account.js, admin.js). Fixed rather than a document-tall background because stretching the mesh down a 10x-viewport page smears the facets into ribbons, and a fixed layer that never moves is the cheapest thing the compositor can hold. Facets land ~41px on a 375px phone and ~64 to 128px on desktop, i.e. 9 to 20 across, bracketing the ~12 of the brief's reference. `height: 100lvh` so a retracting mobile URL bar cannot expose a strip. ~8.5KB gz, vector so one file is exact at every DPR.

- **The ocean layer (v0.3.2, user brief: the mesh should swell like water and the color should drift).** `src/modules/oceanMesh.js` adds `canvas.site-bg__canvas` inside `div.site-bg` and animates the same lattice in WebGL. The static SVG **stays underneath as the floor** and is what paints pre-bundle, with JS off, under `prefers-reduced-motion`, when WebGL is missing, and on context loss; the canvas only gets `is-live` (opacity 1) after frame zero is drawn, so there is no flash and the crossfade is between two states of one mesh, not two designs.
  - **WebGL is the cheap option here, not the expensive one.** Canvas 2D would mean 800 `fill()` calls per frame on the main thread, competing with Lenis, GSAP and the Matter.js field; SVG/CSS cannot move vertices at all. WebGL is one draw call of 2400 vertices with displacement in the vertex shader. Measured: draw submission ~0.0003ms, and the fragment shader is one varying plus a hash.
  - What holds the cost down, all of it load bearing: **one draw call**, buffers uploaded once (only uniforms change per frame), **30fps cap**, backing store pinned to **DPR 1** (adjacent facets differ by a few levels so there is nothing for extra resolution to sharpen, and it is a 4x fragment saving on 2x displays), fully parked on `visibilitychange`, and parked on context loss until it is restored. **Do not add a per frame `getBoundingClientRect`** — sizing is driven by a debounced `ResizeObserver`, because reading layout every frame would make the background the most expensive thing on the page. Note that none of the v0.3.4 changes cost a frame: bigger amplitude and a wider palette are different numbers in the same uniforms, not more work.
  - Sizing uses `ResizeObserver` on the canvas, not a window `resize` listener: this fixed layer changes width by the scrollbar once the perk field grows the page past one screen, which no window event reports.
  - **Not weird** is a verified property, not a hope, and `scripts/check-swell.mjs` is where it is verified. Amplitude is **13.5 mesh units** against a 70 unit cell (7 through v0.3.3, 18 at v0.3.4, trimmed 25% at v0.3.5 on the user's word): measured peak vertex displacement 37.1 units, **52.9% of a cell**, with **zero inverted facets** and the smallest facet holding 0.799x its rest area (0.771x at the mobile cap). Drawn at `OVERSCAN` 1.08 (56 units of margin against a 30 unit worst case), verified empirically at v0.3.4 too: zero edge gap pixels over 150 frame sweeps at 1440x900, 390x844 and 844x390, and the margin only got safer since.
  - **The lever that made the motion 3x stronger was WAVELENGTH, not amplitude.** Facets tangle on the local *shear* of the displacement field, not on how far it travels, so long waves let neighbouring vertices move together and the surface heaves as one body. The first v0.3.4 attempt kept the v0.3.2 wavelengths and just raised amplitude; the gate failed it at 0.36x rest area. Stretching every wavenumber by 1/0.7 at the same amplitude took the same motion to 0.74x. If more power is ever wanted again, lengthen the waves first.
  - Colour drift walks `PALETTE_CYCLE` over **64s** (96s and three stops through v0.3.3), now **four stops spread across the wheel**: rose, cool lavender, warm apricot, soft mauve, all within ~0.01 relative luminance of each other. Equal luminance is the whole trick, it is what lets the hue travel this far without moving the contrast budget. The stop order is chosen so every crossfade *midpoint* lands back in the rose family, so the extremes read as the page leaning warm or cool and the crossings read as home. Plus a **±0.15** slide of the ramp itself (±0.06 before) so light appears to move across the surface; it is bounded and the ramp clamps, so the deep end still resolves to the same stop.
  - **Contrast is measured against rendered pixels, not stop values.** At v0.3.4 the whole cycle was rendered on a GPU at three viewports and every pixel read back: darkest rendered pixel `rgb(220,191,202)`, giving `--ink-soft` **4.76:1**, `--ink` 10.57:1, `--accent` 5.61:1. Above the 4.5:1 AA floor at every instant, at every viewport.
  - **Mobile (v0.3.4, user report that none of this happened on a phone).** Three causes, only one of them fatal. (1) **Context loss was terminal**: mobile GPUs drop WebGL contexts routinely when you leave the tab, and the old handler revealed the static mesh and never came back, so a phone typically animated once per page load and then looked permanently still. `webglcontextrestored` now rebuilds the program and buffers, re-fits, and eases the swell back up from flat. This was the actual bug. (2) **A 30Hz device ran at 15fps**: Low Power Mode and battery savers cap rAF at 30fps, which lands just under this module's own 30fps gate once timer coarsening applies, so every second frame was rejected; `FRAME_SLACK` (2ms) fixes it. (3) **The motion was half size in pixels**: `cover` renders the mesh at scale ~0.60 on a phone against ~1.03 on a desktop, so amplitude now compensates for the fit scale, capped at `AMP_SCALE_MAX` 1.15 because the no-inversion proof is written in mesh units and this is what inflates them. Net motion in CSS pixels: **41px desktop, 28px phone** at the v0.3.5 amplitude (55px and 37px at v0.3.4, 17px and 10px before it).
  - The swell now **eases up from flat over 1.6s** (`WAKE_S`), which makes frame zero pixel identical to the static SVG underneath, so the 0.7s reveal is a true crossfade with nothing to jump. Re-run on context restore for the same reason. Before v0.3.4 frame zero was already displaced, which was invisible at amplitude 7 and would not have been at 18.

### Scroll motion system (v0.3.6, user brief: scroll driven animations that look expensive, behave the same on phone and desktop, and stay cheap)

Eleven animations, all scroll driven, all identical at every width (no desktop only or mobile only path anywhere in this set). **The shape of the implementation is the point**: the JS budget had ~5.5KB gz of head room, so nothing here re-implements in JavaScript what CSS already does free. One shot reveals are a single `.is-in` class and the entire look, including the per element stagger, is CSS (`--i` on the child, one `transition-delay` calc in `reveal.css`). Only genuinely scrubbed work gets a frame loop, and every scrubbed animation moves exactly one composited property on one element. Net cost: **+1.3KB gz JS, +0.9KB gz CSS**.

Files: `src/modules/reveal.js` + `src/styles/reveal.css` carry the shared primitives (`.rv-mask`, `.rv-up`, `.rv-rule`, `.is-drawn`); the rest live in the module that owns the element.

1. **Bubble genesis and burst** (the user's headline ask) — see the Perk Field entry below.
2. **Hero departure** — **the copy only since v0.4.0** (64px lift and a fade). The card used to leave with it, travelling 142px and shrinking to 0.84 through a `.hero-card__drift` wrapper; that tween, that wrapper and the v0.3.8 3D turn are all gone on the user's word, and the reason is worth keeping: fading a wrapper that is an ancestor of `.hero-card__tilt`'s `preserve-3d` subtree makes the browser composite the card's layers separately, so on a phone the background mesh read straight through the card. See the v0.4.0 entry below.
3. **Masked title lift** — section eyebrows, titles and notes climb out from behind their own edge, staggered. Once only, so a heading that has arrived can never leave again (the v0.1.x journey lesson). The `.rv-mask` padding/margin pair is the same Fraunces descender fix the hero headline uses; without it `overflow: hidden` shears the tails off g and y.
4. **Divider sweep** — a thread of accent light opens outward along a section's top hairline as you cross it, then dims and leaves the plain rule. `.journey` is the one host with `overflow: hidden`, which clips to the padding box, so its rule sits at `top: 0` instead of `-1px`; that 1px is invisible and is a far smaller change than relaxing that section's clip.
5. **Zone rails** — each perk zone's hairline draws downward while the zone passes. **Replaced the mobile only static edge rail** (`.perk-field__zones::before`), so both platforms now run one mechanic. The accent lives at the *bottom* of the rail's gradient: origin is the top, so the drawn segment's bottom is always the draw front, which puts the bright ink exactly where the line is being laid down for free, with no second animated property.
6. ~~**Nav scroll meter**~~ — page progress filling the navbar's bottom edge. **Removed at v0.3.7 on the user's word**: the `.site-nav__meter` span, its CSS, and the cached `scrollHeight` in nav.js are all gone. Do not rebuild it without a fresh brief.
7. **Ocean surge** — scroll velocity speeds the background swell's **clock**, not its amplitude, and the distinction is the whole reason this is safe: `check-swell.mjs` proves no facet inverts by sweeping 240s of phase at a *fixed* amplitude, so a faster clock only reaches states inside that same family sooner, states a long idle session already reached (`clock` was always unbounded). Raising `uAmp` instead would invalidate the gate outright. Peak hold rather than accumulate, because Lenis fires ~60 events a second against 30 drawn frames and adding per event would ratchet upward. Colour drift and the ramp slide read the same clock, so the whole background leans into a flick. Cost: one multiply per frame, no extra draw.
8. **Journey depth parallax** — the text column drifts against its image (the image already drifts +5% down its frame), so a card resolves into two planes as it crosses. Lands on the `.journey-node__content` container; the children keep their own once only translateX reveal and nested transforms compose.
9. **Orb speed stretch** — the marker riding the draw front elongates along the path and pinches across it in proportion to how fast the front is moving. Direction is the path *tangent* (a probe 6 units ahead), not travel direction, so scrolling back up stretches it the same way instead of flipping it end over end. - **GPU floor (v0.2.9, user report of ~30% GPU at idle).** Two rules hold the line, and both are easy to break by accident:
  1. **No blend or backdrop layer that spans the viewport.** `mix-blend-mode` and `backdrop-filter` read their backdrop, so the compositor snapshots and reprocesses everything behind them on every frame anything moves. The grain uses `background-blend-mode` (above), the nav burger's decorative `backdrop-filter` over an already opaque bar is gone, and the modal's full-screen blur is scoped to `.is-open` so no backdrop root stands by while it is closed. The nav's own `::before` grain multiply is fine: it is 72px tall and blends against its own fill. The v0.3.1 mesh layer is viewport-sized but does **not** break this rule: it blends its own two background layers inside its own paint and never reads what is behind it, which is exactly why the grain there is `background-blend-mode` and not a `mix-blend-mode` sheet.
  2. **No `filter` on a scrubbed or looping element, and no infinite animation off screen.** The journey's draw path carried `blur(5px)` plus a `drop-shadow`, whose filter regions were the path bbox (the whole ~1080x2000px track) re-rendered on every scroll frame; it is now three plain stacked strokes (`--halo` / `--glow` / `--draw`, all scrubbed together from `litPaths` in journey.js) that fake the falloff in the rasterizer. Their opacities were lifted at v0.3.0 (`0.06` to `0.10`, `0.14` to `0.20`) because on the white ground the same stroke subtracts light instead of adding it, and 6% simply vanished; that restores the dark ground's bloom, not more. The ambient ember particles (14 desktop / 8 mobile drifting dots in `.journey__particles`) lost a `blur(0.5px)` here at v0.2.9 and were **deleted outright at v0.3.3** on the user's word (they read as bubbles popping in and out around the Join checkpoint); the wrapper div, the `.journey__particle*` CSS, and the `drifts` array in journey.js are all gone. Everything that still loops forever is gated to on screen: hero card idle float (IntersectionObserver in heroCard.js), orb halo pulse (`.journey__marker.is-active`), and the Join CTA glow (`.journey.is-onscreen`, toggled by journey.js) which animates `box-shadow` and so repaints, not just recomposites.
  Perk field per step: the active-item set is built once into a reused array, `isMobile()` resolves once a frame, and catch-up is capped at 2 substeps so a slow frame cannot stampede the next one.
  3. **The v0.3.2 ocean is the one sanctioned always-on animation, and it earns it.** It is the background, so "gate it to on screen" means gating it to the tab being visible, which it does via `visibilitychange`. It stays within the floor by being one draw call at 30fps at DPR 1 with a trivial fragment shader, and by never reading layout in its loop. If GPU cost is ever reported again, this is the first thing to measure but not automatically the culprit: check for a new viewport-spanning blend or a `filter` on a scrubbed element first, since those were the actual causes at v0.2.9.

## Budgets and floors

- LCP under 2.5s on throttled 4G (live median 1.91s measured at v0.0.2) · CLS ~0 (all media has reserved dimensions).
- JS ≤ **256KB gz**, measured on **index**, which is the page the ceiling was ever about — **95.7KB at v0.4.2** (96.4 at v0.4.1, 97.0 at v0.4.0, 95.9 at v0.3.8, 95.7 at v0.3.6, 94.4 at v0.3.4/v0.3.5). The other pages at v0.4.2: **account 58.5KB gz** of shell plus **49.2KB gz** of Firebase behind a dynamic import (so ~107.7 once signed in traffic pulls it, and the shell's 50.9KB of that is the GSAP/Lenis vendor chunk index has already cached for anyone arriving through the nav link, which is the normal path), and **admin 6.2KB gz** total, which carries neither GSAP nor Lenis nor Firebase. The v0.4.2 index number goes DOWN despite gaining the toast, and the reason is structural rather than a diet, the v0.4.1 note run backwards: a second GSAP/Lenis consumer exists again, so Rollup splits the vendor chunk back out and index no longer pays for the parts of it that only the nav uses. **Do not read a changed chunk filename as a regression; measure the page.** **Raised from 100KB on the user's explicit call, 2026-07-26**, which is the fresh call the old note demanded; the ceiling had been questioned on 2026-07-25 and kept once already. History of what things cost, still the useful part: the ocean layer added ~3.2KB gz at v0.3.2 (module plus the shared mesh geometry), v0.3.4 was net flat, the v0.3.6 scroll motion system **+1.3KB gz** for eleven animations, the v0.3.8 image and type pass **+0.22KB gz** for five more, both only because the looks were pushed into CSS (+0.9 and +0.38KB gz there) and JS kept to thin drivers, and v0.3.9's card typewriter **+1.1KB gz**, most of it the 100 name list, which is data and cannot be pushed anywhere.
  - **The number the ceiling was ever really about is the LCP floor below, not the ceiling itself.** 97KB gz is ~263KB of raw JavaScript a phone downloads, decompresses, parses, compiles and runs before the hero paints, and **~86% of it is libraries, not this site**: GSAP + ScrollTrigger + Lenis are the 142.4KB raw `nav-*.js` chunk, Matter.js is ~84KB of the 120.3KB raw `index-*.js` entry, and every module in `src/` together is roughly 36KB raw. So a feature costing a kilobyte was never the thing worth worrying about. With headroom now, the honest guidance is: **spend it on features, and if the LCP measurement starts slipping, the first move is a lazy chunk for Matter.js**, which is ~84KB raw sitting in the entry chunk for a Perk Field that is section 4 and below the fold on every viewport. That is worth far more than shaving a data file. · card art ≤ 120KB · bubbles ≤ 25KB each · background mesh ≤ 15KB gz (8.5KB; one vector file serves every DPR, so this is the whole background budget).
- Accessibility: semantic landmarks, skip link, focus traps, visible focus everywhere, every bubble labeled ("Name, 20% OFF, opens Instagram"), token pairs hold AA+ contrast on the ground (measured live at v0.3.0 on flat white: body ink 17:1, `--ink-soft` 8.1:1, white on `--accent` 9.54:1, `--accent-2` 5.22:1).
